# M0-B PDF 가져오기·필기·내보내기 계획

**목표:** 사용자가 파일 앱에서 PDF를 가져와 페이지마다 필기하고, 문서를 닫았다 다시 열어 편집한 뒤 필기 포함 PDF를 내보낸다.
**시작 조건:** M0-A의 단일 A4 편집·공통 획·원자 저장·백업 복구 완료. 2026-10-01 재개 요청으로 실행했다. 아래 본문은 원래 계획이며, 실행 판단과 체크리스트는 마지막 절에 기록한다.
**범위:** iPadOS 우선, 로컬 전용. 서버·계정·동기화·협업은 포함하지 않는다.

## M0-A에서 이어받는 결정
- `MiNoteCore` 모델과 JSON은 UIKit·PencilKit 객체에 의존하지 않는다.
- A4 단일 페이지 구조와 schema v1 검증은 현재 단계 범위다. PDF 문서 표현을 추가하려면 기존 사용자 문서를 잃지 않는 명시적 버전 전환이 필요하다.
- 저장소는 한 편집 창만 허용하며 원본 JSON과 직전 정상 백업을 보존한다.
- 시뮬레이터에서 입력·저장·복원을 확인했으며 Apple Pencil 반응과 손바닥 입력은 실기기 검증 대기다.

## 단계 1 — PDFKit과 필기 캔버스 좌표 기술 검증
- 소형 격리 실험 앱 또는 스파이크 브랜치에서 PDFKit 페이지 위에 PencilKit 오버레이를 표시하고 입력·undo/redo를 확인한다.
- iOS 18 호환성을 기준으로 PDFKit 오버레이 API와 페이지 뷰 수명주기를 조사·검증한다. 페이지 이동과 PDFView 재사용·확대 후 오버레이가 중복 생성되거나 획이 사라지지 않는지 시험한다.
- 테스트 PDF에 media box와 crop box가 다른 페이지, crop box의 0이 아닌 원점, 0·90·180·270도 회전을 넣는다.
- PDF 좌표(일반적으로 좌하단 원점)와 MiNote 좌표(좌상단 원점, 72pt/in) 간 변환을 왕복 테스트한다. 화면 줌을 해도 문서 좌표가 바뀌지 않아야 한다.
- 페이지 화면 회전, 분할 화면, 서로 다른 화면 배율도 검사한다. 검증 전에는 최종 캔버스·좌표 어댑터 구조를 확정하지 않는다.

## 단계 2 — PDF 자산·문서 모델·마이그레이션
- PDF 원본은 앱 Documents 디렉터리에 별도 자산으로 복사하고 JSON 문서에는 상대 자산 식별자, 원본 파일명·페이지 수·가져온 날짜와 페이지별 필기 목록을 저장한다.
- 외부 파일 URL을 오래 보관하지 않는다. 파일 선택 이후 보안 범위 접근과 파일 조정 규칙을 적용해 복사 완료까지 권한을 유지한다.
- 기존 A4 문서를 열었을 때 내용과 ID를 보존하는 schema v1 → 새 스키마 마이그레이션을 설계한다. 알 수 없는 미래 버전, 잘린 PDF, 비밀번호로 잠긴 PDF, 빈 문서는 원본을 보존하고 사용자에게 오류를 표시한다.
- 스키마 전환 중 프로세스 종료에도 원본 PDF, 현재 JSON, 이전 백업 중 적어도 하나의 복구 가능한 상태가 남는 저장 순서를 정의한다.
- 가져오기 제한(페이지 수·파일 크기·메모리 사용)은 실제 PDFKit 측정 후 합리적인 사용자 안내와 함께 결정한다. 큰 문서를 한 번에 래스터화하지 않는다.

## 단계 3 — 다중 페이지 렌더링·주석 영속화
- 페이지를 필요할 때 렌더링하고 멀리 떨어진 페이지의 뷰와 비트맵은 메모리에서 해제한다. 현재 보이는 페이지와 주변 페이지의 메모리 상한을 측정한다.
- 각 페이지의 PencilKit 획은 플랫폼 독립 `InkStroke`로 보존한다. PDF 원본 페이지와 주석은 개별 데이터로 두어 원본 PDF 품질·텍스트 검색성을 저장 과정에서 훼손하지 않는다.
- 확대·스크롤·페이지 전환, undo/redo, 앱 백그라운드 전환 뒤 저장, 앱 재실행 후 페이지별 편집 복귀를 검증한다.
- 저장 상태는 현재 페이지 변경만이 아니라 문서 전체 리비전에 대해 일관되게 표시한다. 동시 편집 창은 M0-A와 같이 허용하지 않는다.

## 단계 4 — PDF 내보내기
- 원본과 주석을 합성한 새 PDF를 만든다. 내보내기는 원본 파일을 교체하지 않고 목적 파일을 임시 출력 후 원자적으로 완성한다.
- PDF 확대·축소에서도 획 품질이 유지되는 벡터 출력을 우선한다. M0-B 범위가 각 필기 페이지를 원본 PDF와 눈에 띄게 달라지지 않게 합성하는지 fixture로 판정한다.
- 페이지 크기·회전·crop box를 보존한다. PDF 텍스트·링크·주석 같은 원본 요소를 보존할 수 있는지 스파이크에서 확인하고, 보존되지 않는 요소가 있으면 사용자에게 내보내기 영향과 범위를 명확히 알린다.
- 출력 전 페이지 수·페이지 경계·획 위치를 검증하고 iPadOS 미리보기에서 열린 결과를 시각 확인한다. 공유 시트로 파일 앱 등에 내보낼 수 있게 한다.

## 테스트와 완료 조건
- 기존 schema v1 A4 샘플을 새 버전으로 열고 저장해도 제목·페이지·획 ID·좌표·색상·내용이 유지된다.
- PDF 여러 페이지를 가져와 각 페이지 위에 서로 다른 획을 넣고, 회전·crop box를 거친 전후 문서 좌표가 허용 오차 내에서 같다.
- 파일 앱에서 가져온 문서는 강제 종료 후에도 다시 열리며, 해당 원본 자산과 주석의 ID가 유지된다.
- 읽기 불가·손상·잠금 PDF와 가져오기 중 저장 실패는 원본 및 기존 노트를 덮어쓰지 않는다. 저장 실패 시 필기는 화면 메모리에 남고 재시도 가능하다.
- 필기 포함 내보낸 PDF를 다시 열어 페이지 수·크기·방향·경계를 자동 확인하고, 시각 비교로 획 잘림·위치 어긋남을 확인한다.
- 공통 패키지, iPadOS 18.6 및 26.4 시뮬레이터 앱 테스트 통과. Apple Pencil 및 손바닥 테스트의 미실행 여부를 별도로 기록한다.

## 보류할 범위
- iCloud 동기화, 계정, 공동 작업, Windows·Android·macOS·iPhone 지원.
- OCR·검색, PDF 텍스트 편집, 폼 채우기, 첨부 오디오, 손글씨 인식, 이미지·스티커, 여러 노트북·폴더.
- 검증 전 구현 세부 사항(페이지 오버레이 구현 선택, 복잡한 원본 PDF 요소의 내보내기 충실도, 성능 상한).

## 실행 판단과 완료 체크리스트 — 2026-10-01

- 사용자의 main 직접 작업 지시를 따라 별도 spike 브랜치/worktree를 만들지 않았다. 직접 구현 후 별도 에이전트가 전체 M0-B 변경을 한 번 리뷰했다.
- PDFView overlay 대신 `PageZoomHost` 안에 PDF 배경과 단일 `PKCanvasView`를 둔다. 현재 페이지를 명시적으로 전환하고 좌표는 회전된 crop box의 좌상단, 72pt/in로 통일했다. PDF 뷰/bitmap을 전체 페이지 수만큼 보관하지 않는다.
- schema v2와 원본 PDF 자산을 분리한다. 기존 A4를 보존하고 한 PDF만 추가한다. 자산을 먼저 원자 저장한 뒤 리비전을 검사해 JSON을 저장한다. 자산 누락은 빈 노트 복구로 숨기지 않는다.
- PencilKit 공개 API의 출력 범위를 반영해 필기만 최대 216dpi/4096px 이미지로 합성한다. 벡터 필기 출력은 보장하지 않는다. 원본 텍스트/벡터와 보이는 crop 위치·회전은 검증했으며 PDFKit 출력의 MediaBox 원점 정규화, 양식/원본 주석 고정화와 일부 링크 영향은 사용자에게 안내한다.
- 가져오기 상한은 100MB/500페이지/한 변 2000pt다. 500페이지 소형 vector fixture의 메모리를 측정했지만 실제 큰 이미지 PDF나 실기기 성능을 입증하는 값으로 사용하지 않는다.
